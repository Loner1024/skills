# 分类：何时画图、画哪种、怎么画

本文件是 `tech-diagrams` skill 的决策依据，也是给人看的速查表。规则来源见 `FINDINGS.md`。

## 1. 决策阶梯（任何一关不过就不画）

1. **读者必须"看见结构/时序"才能理解吗？** 纯线性步骤、可枚举的里程碑与原则、单个数字 → 用编号列表/要点/正文，不画图。
2. **图和正文会不会说同一件事？** 如果图只是把段落复述一遍，删掉图（或删掉那段重复的正文）。图要提供正文无法高效给出的信息：拓扑、时序、状态空间、比例。
3. **内容是否稳定？** 频繁变动且无维护计划的架构图会变成负债（Mintlify 的证据）。
4. **能否用表格更精确？** 多属性精确对照 → 真表格（`<table>`），不要画成"伪表格图"。
5. **密度是否超预算？** 节点 >9 或连线交叉 ≥2 → 拆成"总览 + 细节"两张，或用 zone 分区。

## 2. 反例清单（五家都不这么干）

- 线性流程（安装步骤、顺序操作）画成 5 个框加箭头。
- 一个框加一个标签的"图"。
- 与正文逐句重复的示意图。
- 用装饰性渐变/发光/网格来"显得技术"。
- 图例替代直接标注。
- 在图中放整段文字（框内永远是名词短语）。
- 伪造产品界面截图或伪造基准数据。

## 3. 类型表（13 类 / 4 族 + 1 个可叠加的窗口框架）

计数方式：前 13 行分属四个**内容族**（结构 / 时序 / 数据 / 叙事），每族对应一个 `references/type-*.md`；第 14 行"窗口框架"是叠加在任意内容族之上的**外框**（`type-ui.md`），它换的是 chrome，不是语法，所以不算第五个族。

| 族 | 类型 | 何时用 | 语法要点 | 常见错误 |
|---|---|---|---|---|
| 结构 | **架构拓扑** | 组件 + 连接 + 边界（谁调用谁、在哪运行） | zone 带（大写等宽小标签）分区；实线=数据面，虚线=控制面/可选/回程；节点写真实服务名 | 所有盒子一个样式（丢失层级）；连线穿越无关节点 |
| 结构 | **数据流** | 数据在阶段间被变换、聚合、分片 | 阶段从左到右；store 用卡片/柱体 + 等宽 key；每个阶段标输入→输出 | 混淆"数据流"与"调用顺序"；缺少 key/单位 |
| 结构 | **分层 / 嵌套** | 抽象层级、渲染树、容器与作用域 | 从外到内递进；层名左对齐；只画相邻两层的交互 | 层数 >5；把不同抽象层级混在一张图 |
| 结构 | **循环 / 飞轮** | agent loop、evaluator-optimizer、反馈回路 | 环形布局；**条件写在弧线上**（"Until tests pass"）；带决策节点与显式出口（"(x) Exit loop"） | 用直线流程图表达循环；出口条件缺失 |
| 时序 | **序列图** | 多参与者消息往返（协议、握手、工具调用） | 演员列 + 生命线；>6 步考虑步进式或拆分；箭头标 payload 名（`tools/call`） | 把 10+ 步塞进一张静态图；箭头无名字 |
| 时序 | **生命周期 / 管线** | 请求生命周期、构建管线、部署链路 | 左→右 stages，可编号；gate/特殊节点用唯一强调色 | 阶段粒度不一致（有的画进程、有的画函数调用） |
| 时序 | **状态机** | 状态 + 迁移 + 守卫 | 守卫标在迁移上；不画不可达状态；初始/终止态明确 | 把"步骤"当"状态"；迁移缺触发条件 |
| 时序 | **泳道 / 角色** | 跨角色的交接（client/edge/origin） | 每条泳道一个角色；交接点标协议与方向 | 泳道内塞子流程 |
| 数据 | **基准条形** | 数量对比（质量、吞吐、成本） | 标题=结论；基准名 + 一句 gloss；值标注；星号脚注写口径与样本数 | 无口径、无样本数；用截断轴夸大差异 |
| 数据 | **趋势 / 分位** | 随时间变化；p50/p95/p99 | 直接标注系列名，尽量不用图例；分位图标注轴含义 | 多系列堆叠无重点；纵轴无单位 |
| 数据 | **前后对比 / 权衡** | 变更前后；两难取舍 | 成对图同尺度；权衡用曲线或象限散点并标出选择点 | 前后图尺度不同；只画"好结果" |
| 叙事 | **时间线 / 甘特** | 阶段计划、重叠执行、并发调度 | 行=资源，列=时间；重叠区用色块；标注关键路径 | 把里程碑列表画成甘特 |
| 叙事 | **象限 / 对比矩阵** | 两轴定位、方案取舍 | 轴标含义；象限名写结论（"Higher satisfaction and lower cost"） | 四象限无轴说明；点无标签 |
| 框架 | **窗口框架图**（可叠加在任意族上） | 终端/IDE/浏览器中的界面示意 | 窗口 chrome（tab bar / 流量灯）+ 等宽内容；只画必要 UI | 伪造真实产品截图；界面元素过多 |

表格降级规则：精确多属性（>4 列或需逐行查阅）→ 用真表格；二元对比 → 表格；单数字 → 正文或大数标注。

## 4. 风格 register（默认 + 备选）

| register | 画布 | 强调色 | 字体 | 适用 |
|---|---|---|---|---|
| **technical-dark（默认）** | `#0A0A0B`，面板 `#111214`，发丝线 `rgba(255,255,255,.08)` | `#5E6AD2`（焦点 ≤2 元素） | 标签 Inter，标识符 SF Mono/Menlo | 工程文档、README、技术博客（Linear/Vercel 语汇） |
| **light（Vercel/Geist）** | `#FAFAFA`（Geist background-200），卡片 `#F2F2F2`，发丝线 `#C9C9C9`，墨 `#171717` | `#0072F5`（Geist blue-700，焦点 ≤2 元素） | 标题/标签 Inter 或 Geist Sans，标识符 mono（无衬线） | 产品文档、技术博客、浅色站点（Vercel/Geist 语汇，无纯黑纯白，色彩落在组件上） |
| blueprint | `#ffffff` + 引导线（非装饰，须有用途） | 黑墨 + 单色数据色 | 等宽为主 | 基础设施/网络/部署图（Vercel 语汇） |
| product-frame | 随 register，套窗口框架 | 同上 | 内容等宽 | 终端/IDE/浏览器界面示意 |

## 5. 交付与文案规范

- **caption = alt**，且 caption 给出 takeaway（不是"图 1：架构图"）。
- 图前正文要有一句引出语，图不与正文逐句重复。
- SVG 必须有 `<title>`（≤60 字）与 `<desc>`（一句话说明内容而非几何），根节点 `role="img"`。
- 深色图配浅色版本（或明确说明仅深色可用）；嵌入网页时提供 `prefers-color-scheme` 切换。
- 文件命名：`<slug>.html`（预览）/ `<slug>.svg`（交付）；成对时 `<slug>-dark.svg` / `<slug>-light.svg`。

## 6. 密度与几何预算（硬约束）

- 节点 ≤9；连线交叉 ≥2 即拆图。
- 4px 网格对齐；圆角 ≤8px；线宽 1px（强调线 1.5px 上限）。
- 正交连线（转角 8px 圆角）；禁止对角线；两条线不得共线/重叠。
- 箭头标签必须有遮罩，标签与线留 6–10px 间隙；标签不压线、不压节点。
- 画布四周留白 ≥16px；字号阶梯固定（如 20/14/12/11），不出现 11 以下正文。

## 7. 校验分工

- **脚本能查**（`scripts/self_check.py` + `scripts/render.sh`）：SVG 结构合法性、`title/desc/role`、节点与连线预算、网格对齐、字体栈是否含 CJK 兜底、渲染是否成功、尺寸与留白、是否为空白图。
- **人眼必须查**：视觉重心、光学对齐、线宽手感、字体气质、图的"说服力"。
- 由于本环境模型无图像输入能力，**"渲染后看图"这一步必须由人完成**；脚本负责把所有可自动化的错误挡在交付前。
